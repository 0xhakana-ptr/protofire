# Architecture decisions outside `arch/`: the census
# `scripts/check-arch-fanout.sh` ratchets.
#
# Each row is `<file> <occurrences>  # <reason>`: how many times that file names
# `x86_64`, `aarch64` or `riscv64` in a `target_arch` gate (line comments
# stripped first), and why it names one at all.
#
# A row's reason is one of exactly two things, and the gate refuses a row that
# gives neither:
#
#   * `fact:` — a fact about the machine.  An ABI record only one architecture
#     has, a driver for hardware only one machine has.  A fourth architecture
#     does have to decide what it does here; there is nothing to shim.
#
#   * `gap:` — a question the architecture should be answering, and the fix is
#     to move it behind `arch/`.
#
# The number this file is for is zero, and the honest way there is one file at a
# time.  A row that grows fails with its own reason printed, because a reason
# that covered the old count may not cover the new one.
#
# ## Zero, and why it is now zero
#
# The one row this file used to carry was `bootloader/src/main.rs`, five
# `target_arch` gates in the entry symbol, the panic handler and three
# `halt_forever` arms.  Its reason said those were things only a binary can
# define, which was true and was not the question: the *symbol* is a binary's,
# but the *instruction* it reaches for is the machine's.
#
# `bootloader` is the protocol — a loader put us here, so start the kernel —
# and `arch` is the machine.  The five gates were five places the machine was
# named in the crate that is not the machine.  Moving them leaves one neutral
# `protofire_entry` that every machine's assembly calls, and the stop behind a
# panic is `arch::halt`, which is one name for `hlt` and `wfi` rather than
# three spellings of them here.
#
# The row is gone rather than rewritten because there is nothing left for it to
# describe.  A row would have to be re-argued to come back, which is the point
# of recording to zero.

# 0 file(s), 0 occurrence(s) outside arch/

apps/init/src/main.rs 18  # fact: a ring-3 program's syscall gate is its machine's — `int 0x80`, `svc` and `ecall` are three encodings of one ABI, and the arch layer's own gates cannot speak for a program the arch layer does not link.  Six per call and three calls before the memory ones: `open`, `read` and `exit` cost nine, and `mmap` and `brk` add six more because a program that wants memory has to spell the call the same way it spells the others.  The bound is real and it is this: a new architecture teaches this file five calls, not one, and the alternative — a trait the arch layer implements for a program it does not link — is a layer that exists only on paper.
